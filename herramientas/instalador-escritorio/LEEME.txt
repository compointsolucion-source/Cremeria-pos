INSTALADOR DE COMPOINT PUNTO (pantalla en Go)
=============================================

QUE ES
La pantalla bonita (panel lateral, Predeterminado / Avanzado, elegir carpetas)
con la que el cliente instala Compoint Punto en Windows. Es un .exe pequeno
hecho en Go (solo biblioteca estandar, sin dependencias). Abre una ventana de
Edge/Chrome en modo "app" que muestra una pagina local (ui/index.html) servida
por el mismo .exe en 127.0.0.1 con un puerto al azar y una clave de sesion.
Mismo diseno que el Asistente del servidor.

Por si solo NO instala nada: lleva pegado al final el instalador del programa
(el "paquete" de electron-builder) y lo ejecuta en silencio con la carpeta
que el cliente eligio. Lo arma escritorio/scripts/empaquetar-instalador.js.

FORMATO DEL ARCHIVO FINAL
  [ este .exe ][ paquete (NSIS) ][ datos JSON ][ pie de 64 bytes ]
  pie: bytes 0-7  "CPTINST1"
       bytes 8-15 largo del paquete (uint64, little endian)
       bytes 16-23 largo de los datos JSON (uint64 LE)
       bytes 24-55 sha256 del paquete
       bytes 56-63 "CPTFIN01"
  datos JSON: formato, version, negocio, archivo, tamanoInstalado, conUrl.
  Si el sha256 no coincide el instalador lo dice y borra el archivo copiado.
  Sin paquete pegado el .exe abre en modo "sin paquete" (solo para desarrollo).

PROBARLO SIN WINDOWS (modo simulado)
  cd herramientas/instalador-escritorio
  go build -buildvcs=false -o inst .
  ./inst --simulado --sin-ventana --puerto 8780 --token prueba
  y abrir  http://127.0.0.1:8780/?t=prueba  en un navegador.
  En Linux/Mac el modo simulado es automatico. Finge los discos C: (fijo),
  D: (fijo) y E: (USB) y un arbol de carpetas en memoria; no escribe nada.
  Opciones: --simulado  --sin-ventana  --puerto N  --token T  --carga archivo
  Variables para forzar situaciones (todas opcionales):
    INSTALADOR_SIM_ERROR=carpetas|copiar|accesos|config   falla ese paso
    INSTALADOR_SIM_ADMIN=1         ya es administrador
    INSTALADOR_SIM_UAC=no          el usuario cancela el permiso (UAC)
    INSTALADOR_SIM_ESPERA=ms       que tan lento avanza
    INSTALADOR_SIM_DATOS_EXISTENTES=1   ya hay una base de datos
    INSTALADOR_SIM_YA_INSTALADO=1       ya hay un Compoint instalado
    INSTALADOR_SIM_ABIERTA=1       el programa esta abierto (se cierra solo
                                   despues del primer aviso)
    INSTALADOR_SIM_POCO_ESPACIO=1  C: casi lleno
    INSTALADOR_SIM_SIN_USB=1       no hay memoria USB
    INSTALADOR_SIM_NEGOCIO=nombre  nombre del negocio
    INSTALADOR_SIM_CONURL=1        el paquete trae direccion del cliente
    INSTALADOR_SIM_HANDOFF=archivo donde escribe el instalacion.json simulado

PRUEBAS AUTOMATICAS
  go vet ./...
  go test ./...
  GOOS=windows GOARCH=amd64 go vet ./...        (revisa la parte de Windows)
Cubren: rutas, validaciones, formato del paquete, archivo que se le deja al
programa y el servidor completo (flujos, seguridad, errores, reintentos).
La compatibilidad con el paquete que arma Node se prueba desde escritorio/:
  node --test

COMPILAR EL .EXE PARA WINDOWS
  ./construir.sh [salida.exe]        (por omision escritorio/dist/instalador-base.exe)
Equivale a:
  CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -buildvcs=false -trimpath \
    -ldflags "-H=windowsgui -s -w" -o salida.exe .
El icono, el manifiesto (sin pedir administrador) y los datos de version van
en rsrc_windows_amd64.syso. Para regenerarlo (si cambia el icono o la version):
  REGENERAR_RECURSOS=1 ./construir.sh        (usa recursos/generar_syso.py)
En GitHub se compila solo en el flujo "Instalador de escritorio (Windows)".

ARCHIVOS
  main.go        servidor local, rutas de la API, pasos de la instalacion
  tipos.go       tipos, validaciones de carpetas, mensajes
  rutas.go       ayudas para rutas de Windows (D:\Carpeta\Sub)
  carga.go       lee y extrae el paquete pegado al final del .exe
  handoff.go     arma el instalacion.json que lee el programa
  utiles.go      registro (log) y cosas chicas
  windows.go     lo propio de Windows: discos, permisos, accesos, lanzar NSIS
  otros.go       lo mismo para otros sistemas (usa el modo simulado)
  simulado.go    Windows de mentira para probar
  ui/            la pantalla (index.html + imagenes)
  recursos/      icono, manifiesto y generador del .syso
  *_test.go      pruebas

QUE HACE AL INSTALAR (resumen)
  1. Valida las carpetas (disco fijo, espacio, permisos, no dentro unas de
     otras, base de datos existente, programa abierto).
  2. Ejecuta el paquete:  Paquete.exe /S /allusers|/currentuser /D=<carpeta>
     (pide permiso de administrador solo si la carpeta lo necesita).
  3. Borra los accesos directos que el cliente desmarco.
  4. Escribe %LOCALAPPDATA%\CompointPunto\instalacion.json para que el
     programa aplique el modo y las carpetas la primera vez que abra.
  El registro queda en %TEMP%\CompointInstalador\instalador-log.txt.

SEGURIDAD
  Solo escucha en 127.0.0.1, exige la clave de sesion y revisa el Host de cada
  peticion. Una sola instancia a la vez. Se cierra solo si cierran la ventana
  (90 s sin latido) y nunca mientras esta instalando.

LIMITE CONOCIDO
  El .exe no esta firmado digitalmente, asi que SmartScreen puede mostrar
  "Windows protegio su PC" la primera vez (Mas informacion -> Ejecutar de
  todas formas). Un certificado de firma de codigo lo evitaria.
